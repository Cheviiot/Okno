# Протокол Okno, версия 1

## Транспорт

TCP, порт по умолчанию **21200**. После подключения стороны выполняют
рукопожатие `Noise_XX_25519_ChaChaPoly_BLAKE2s` с прологом `okno/1`.
Инициатор — клиент. Сообщения рукопожатия передаются как записи
`u16 BE длина || данные`.

Каждое устройство имеет постоянный ключ X25519 (`identity.key`). Отпечаток —
SHA-256 открытого ключа, 64 hex-символа; людям показываются первые 16 байт
группами по четыре символа. Клиент хранит отпечатки хостов (`trust.toml`)
и сравнивает при каждом подключении:

| Результат | Действие клиента |
|---|---|
| ключ известен на этом адресе | подключиться |
| ключ известен, адрес новый | подключиться, запомнить адрес |
| ключ новый | показать отпечаток, спросить |
| на адресе был другой ключ | громкое предупреждение |

После рукопожатия каждая запись — транспортное сообщение Noise (nonce — счётчик
записей в данном направлении, начиная с 0):

```text
record    = u16 BE длина || ciphertext          (≤ 65535 байт)
plaintext = channel u8 || flags u8 || fragment  (flags bit0 = FIN)
```

Прикладное сообщение (`Envelope`, protobuf, ≤ 32 МиБ) делится на фрагменты;
последний помечен FIN. Отправитель чередует фрагменты по приоритету каналов,
получатель собирает их по каналам:

| Канал | № | Сообщения |
|---|---|---|
| Control | 0 | Hello, Login, HostInfo, Ping, Clipboard, Video/AudioControl, Stats |
| Input | 1 | InputEvent, Terminal |
| Audio | 2 | AudioPacket |
| Video | 3 | VideoFrame (очередь 3 кадра, лишние отбрасываются) |
| Bulk | 4 | File, Tunnel |

## Сеанс

1. Клиент → `Hello{version, device_name, os}`. Хост отвечает своим `Hello`;
   при другой версии хост шлёт `Error` и закрывает соединение.
2. Клиент показывает пользователю отпечаток (при необходимости) и шлёт
   `Login{username, password}`.
3. Хост проверяет Argon2id (m = 64 МиБ, t = 3, p = 1), не более 4 проверок
   одновременно. Первые 3 ошибки с одного адреса (IPv6 — с /64) бесплатны,
   дальше задержка 2, 4, 8 … 60 с; счётчик забывается через 15 минут без ошибок.
   Ответ `LoginResult{status, retry_after_ms}`. На одном соединении до 5 попыток.
4. После успеха хост шлёт `HostInfo{displays, mac_addresses, services}`.
5. Дальше — сообщения служб; `Ping`/`Pong` для проверки задержки, `Close` для
   завершения.

До TCP-рукопожатия хост проверяет адрес клиента по списку разрешённых сетей
(по умолчанию: loopback, частные, link-local и CGNAT-диапазоны).

## Рабочий стол

- `HostInfo.displays` перечисляет мониторы хоста; клиент шлёт
  `VideoStart{display, max_fps, bitrate_kbps}` (0 — значения хоста: 30 fps, 8 Мбит/с).
- `VideoFrame` — один access unit H.264 Annex B (constrained baseline, без
  B-кадров), размеры чётные. Если очередь видео отправителя переполнена, кадр
  отбрасывается и следующий кодируется как ключевой; получатель при ошибке
  декодирования или переполнении своей очереди шлёт `KeyframeRequest` и
  пропускает кадры до ключевого. Ключевой кадр также раз в 10 секунд.
- Ввод: `PointerMotion` — абсолютные координаты 0..1 внутри монитора;
  `PointerScroll.steps_*` — щелчки колеса (положительные — вниз и вправо),
  `dx/dy` — плавная прокрутка в логических пикселях; `KeyEvent.evdev_code` —
  физическая клавиша по кодам Linux evdev (`KEY_*`), Windows переводит их в
  скан-коды набора 1.

## Буфер обмена

`ClipboardText{text}` в любую сторону, до 1 МиБ UTF-8. Хост отправляет текст,
когда его скопировали на хосте; клиент — когда окно сессии снова получает
фокус и локальный буфер изменился. Полученный текст обратно не отправляется.

## Файлы

`FileMsg{id, op}`; `id` выбирает клиент, хост повторяет его в ответах.

```text
список:      C ListDir(path)        → H Listing{path, entries, parent, separator} | Failed
скачивание:  C Download{path}       → H Accept(size), Chunk{offset,data}…, Done(sha256) | Failed
отправка:    C Upload{name, size}   → H Accept(0)
             C Chunk…, Done(sha256) → H Done(sha256) | Failed
отмена:      C Cancel
```

Пустой путь в `ListDir` — домашний каталог пользователя хоста; скрытые файлы не
показываются. Отправленные файлы попадают в «Загрузки» хоста под свободным
именем (`имя (2).ext`), пишутся в `имя.okno-part` и переименовываются только
после совпадения SHA-256. Куски по 256 КиБ идут по каналу Bulk.

## Звук

Клиент шлёт `AudioControl{enabled}`; хост захватывает то, что воспроизводит его
аудиовыход (монитор устройства по умолчанию в PipeWire, WASAPI loopback в
Windows), и отправляет `AudioPacket{seq, data}` — Opus, 48 кГц, стерео, кадры по
20 мс, 96 кбит/с. Пакеты, не поместившиеся в очередь канала Audio, отбрасываются.
Клиент держит джиттер-буфер 60 мс (не больше 200 мс) и маскирует до пяти
потерянных пакетов подряд средствами Opus.

## Терминал и проброс портов

```text
терминал:  C Open{cols,rows} → H Data… ; C Data (клавиши), C Resize, C Exit (убить)
           H Exit(code) по завершении оболочки
туннель:   C Open("host:port") → H Opened(bool); Data в обе стороны; Closed с любой стороны
```

Терминал — PTY на хосте с оболочкой пользователя (`$SHELL`; PowerShell на
Windows), `TERM=xterm-256color`. Туннель: клиент слушает локальный порт, каждое
соединение — отдельный `id`; хост подключается к адресу так, как видит его сам.

## Обнаружение

- **mDNS**: служба `_okno._tcp.local.`, экземпляр `<имя>-<8 hex отпечатка>`,
  TXT: `v` (версия), `name`, `os`, `fp` (отпечаток hex).
- **UDP broadcast**, порт **21201**: запрос `"OKNO" 0x01`; ответ хоста
  `"OKNO" 0x02 || Announcement{version, name, os, fingerprint, port}` на адрес
  отправителя.
- **Wake-on-LAN**: magic packet на UDP 9 всех broadcast-адресов; MAC-адреса хост
  сообщает в `HostInfo`.

Номера полей сообщений — в `crates/okno-proto/src/messages.rs`; их нельзя
переиспользовать.
